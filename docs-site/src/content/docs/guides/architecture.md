The oh-my-pi monorepo is organized into three language areas: TypeScript packages under `packages/`, Rust crates under `crates/`, and Python projects under `python/`. The TypeScript packages split into user-facing products (the CLI, extensions, standalone tools) and internal libraries that those products build on. Everything performance-sensitive — search, shell, audio, isolation, language parsing — sits in the Rust native layer behind `@oh-my-pi/pi-natives`, so extension authors never touch Rust directly.

## Rust crates

The `crates/` directory holds the native layer. `crates/pi-natives` is the top-level N-API `cdylib` that implements the JS-visible `@oh-my-pi/pi-natives` surface; the supporting crates — `pi-voice` (mic capture/playback, Opus/WebRTC), `pi-walker` (parallel cache-aware filesystem walker), `pi-shell` (persistent embedded shell with vendored uutils builtins), `pi-uu-diff` and `pi-uu-grep` (in-process shell builtins), `pi-uutils-ctx` (thread-local stdio/cwd context), `pi-ast` (tree-sitter/ast-grep language registry with ~50 grammars), and `pi-iso` (isolation backends: APFS clones, reflink, overlayfs, ProjFS) — are all compiled into that layer, together with the vendored third-party crates in `crates/vendor` (brush-core, `uu-*`, jaq). None of the Rust crates are user-facing or extension-facing on their own; everything reaches users through `@oh-my-pi/pi-natives`. See `docs/native-crates.md` for the full crate-by-crate map.

## This repository's own skills and commands

The repository dogfoods the extension mechanisms it documents. `.omp/skills/` at the repo root holds three project skills — `tool-prompt-optimization`, `system-prompts`, and `semantic-compression` — that steer agent work in this repo, and `.omp/commands/` holds four file-based custom commands (`release`, `review-prs`, `triage`, `fix-issues`) that drive release, PR-review, triage, and issue-fixing workflows. Both mechanisms are user-facing features: see [Skills](/oh-my-pi/extending/skills/) and [Slash commands](/oh-my-pi/reference/slash-commands/) for how the same layout works in any project.
