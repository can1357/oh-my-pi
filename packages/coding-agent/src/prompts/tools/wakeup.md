Schedule one delayed checkback in this persistent top-level interactive session. `delaySeconds` is an integer from 1 through 86400. Supply a self-contained `prompt` (at most 8000 characters), with enough context to act after compaction; it is saved instruction data, not new authority. Latest user intent and current permissions always supersede it.

Use for a delayed follow-up, not for jobs or agents that already auto-deliver. Keep one timer per continuing watch; cancel an obsolete timer instead of stacking watches. Finish the turn after scheduling; `wait` does not block on wakeup timers. At most eight timers may be pending, independently of execution-job capacity.

Optional `check: { command, maxWaitSeconds }` captures a baseline immediately, then runs the same command in the scheduling cwd at each delay. Only changed stdout + exit status wakes the model; unchanged checks repeat without model calls. `maxWaitSeconds` is required, an integer from `delaySeconds` through 86400. Deadline expiry, nonzero exit, a later denied/failed check, timeout, or output overflow forces a one-shot follow-up. Rejected initial approval/preflight fails scheduling. Checks require the enabled native bash tool (not an extension replacement) and run serially with current approvals and guards, at most ten seconds each and 8192 stdout bytes; stderr is discarded and only a SHA-256 digest is saved. Choose a bounded read-only check; its command and the prompt are saved, so never embed credentials.

Read `proc://` for pending timers or `proc://<wakeup-id>` for any saved timer, including terminal state; cancel with `write` to `proc://<wakeup-id>/kill` without content. Once claimed for delivery, a timer may already have fired and cannot be cancelled. Closing OMP or leaving the session suspends timers; reopening the exact saved session restores them, including overdue timers. Forks and new sessions do not inherit them. Closed periods cannot run checks. Delivery is claimed before enqueue: a crash in that gap can lose a wakeup, rather than duplicate it. No exactly-once guarantee.
