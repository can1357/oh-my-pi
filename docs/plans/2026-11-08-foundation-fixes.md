# Foundation Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix Windows null-device redirection, isolate skill-list tests and worker fixtures, and make child handback termination, reserved names, and structured defaults consistent.

**Architecture:** Address W5, then W6, then W1. Keep Windows path translation at the filesystem boundary; release scoped capability bindings and give test worker links the same storage codec as production; validate reserved child tool names before dispatch and terminate only on the same result that was accepted. Update the two README rows and the relevant Unreleased changelogs with their owning tasks.

**Tech Stack:** Rust/pi-shell, Bun/TypeScript, Bun test, Windows and Unix.

**Spec:** `docs/specs/2026-11-08-review-fixes-design.md`, W5, W6, W1 and their W7 documentation only. Other W2–W4 and W7 deliverables are outside this plan.

## Global Constraints

- Paths in commands are relative to the repository root; `src/` and `test/` below otherwise mean `packages/coding-agent/src/` and `packages/coding-agent/test/`.
- Do not alter legitimate user skill discovery or suppress RPC encoding errors to isolate tests.
- `task.structured` defaults to `true`; explicit configuration `false` and the workflow's explicit `structured: false` remain supported, including existing agent-level override semantics.
- `yield` and `handback` are reserved for child sessions; report `tool name "<name>" is reserved` as task validation failure before spawning whenever the registration is available before dispatch. Do not reserve these names globally for unrelated main sessions.
- A successful schema-less structured child with no accepted handback/yield returns its last assistant text with exit 0; schema-bearing missing-yield errors and cancellation semantics remain intact.
- For every defect, demonstrate a regression failing before its fix and passing afterward. Run Windows coverage on Windows. Do not commit unless authorized by the repository owner.

## Investigation evidence (before implementation)

- On Windows, `bun test packages/coding-agent/test/cli/skill-list.test.ts` produced **3 pass, 3 fail**: three exact listings included ambient skills. One invocation of `bun test packages/coding-agent/test/cli/skill-list.test.ts packages/coding-agent/test/thread/integrations.test.ts` ran skill-list first and produced **3 pass, 9 fail**: the same three listing failures followed by six `RpcEncodeError: Cannot send AgentStorage instance across threads (main↔fixture)` failures, with `fixture.stop()` also failing after unsuccessful setup. These are baseline observations, not post-fix results.
- The storage path is not automatic worker-global copying: `runSkillsCommand` discards the release returned by `initializeWithSettings`; `capability/index.ts` retains that Settings in its hold stack. Resetting the Settings singleton and closing AgentStorage do not release the hold or erase `Settings.#storage`. `settingsThreadService` sends `providerSwitches().bound` in its watch snapshot; importing that Settings triggers synchronous `attach`, whose result includes `target.getStorage()`. The integrations fixture omits `runtimeThreadService` on both ends, so the nested AgentStorage has no RPC class codec. Production's full service graph already registers it. Fix both ownership and fixture dependency; closing the database alone is insufficient.
- `CLAUDE_CONFIG_DIR` overrides the passed home and enables Claude user discovery. `.agents` uses `ctx.home` populated from `os.homedir()`; the source alone does not establish why the reported home mock was bypassed. Observe the actual provider context and discovered paths when reproducing the poison-home case; do not invent a second home resolver.
- The existing structured no-schema finalizer test (`executor-warnings.test.ts`, “does not inject missing-submit warning when no schema and raw text exists”) passed in a 24-test run. It proves exit 0 for supplied raw text, not the complete multi-turn path or last-text-only output. The driver may issue three reminders and `monitor.rawOutput()` joins chunks across turns; **[INFERENCE]** multiple text-only turns can therefore return accumulated text rather than only the last. Task 3 tests the complete path before changing it.

## Review Focus

1. `/dev/null` lookalikes and non-Windows hosts must retain their original paths — Task 1 mapping tests.
2. Both output streams and shell existence checks must recognize the Windows null device — Task 1 shell tests.
3. Hostile Claude and `.agents` homes must not contaminate listings; caller environment must be restored — Task 2 poison fixtures and teardown assertions.
4. A live outer capability binding and a persistent settings mirror must survive nested skill-list/worker execution — Task 2 scope and worker tests.
5. Malformed, incremental, and legitimate terminal results must not be confused across events; schema-less text fallback and explicit opt-out must survive — Task 3 monitor and end-to-end tests.
