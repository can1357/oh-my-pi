# A2A Reply Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep pending A2A spawns truthful and make addressed A2A requests complete an owned sender-side job when the addressed Main or subagent replies.

**Architecture:** First give each bridge-created pending spawn a single authoritative state shared by RPC and SSE. Then keep outgoing reply expectations in a main-thread, process-wide registry exposed to workers as a thread service; the caller's existing scoped async-job manager owns the wait and routes its result. Receiver wake-turn finalization consumes the same incoming-request record as explicit replies and sends its final text over A2A.

**Tech Stack:** TypeScript, Bun, JSON-RPC 2.0, SSE, existing async jobs, IRC bus and worker-thread RPC.

**Spec:** `docs/specs/2026-11-08-review-fixes-design.md`, W3, W2 and their A2A-specific W7 consequences. Paths below are relative to the repository root. Read the spec before implementation.

## Global Constraints

- Order W3 before W2. W1 precedes W3 in the spec's overall dependency graph; use the checkout's actual W1 state and do not implement W1 here.
- `a2aSpawn: true` remains the existing task-backed `GetTask` path; this plan changes addressed delivery only. Do not change `wait` semantics, transport authentication, or transfer an incoming request's responsibility from Main to a child.
- `a2a.replyTimeoutMs` is `1_800_000` by default; `0` disables the reply deadline. `a2a.clientTimeoutMs` remains the distinct transport budget.
- One process-wide outgoing registry lives in main, not in session-local `A2aAgentBridge` or one per worker. Job ownership remains scoped to the caller's root manager and caller agent ID.
- Keep existing terminal-generation and cancellation protections, IRC behavior for nonmatching/late replies, and Main's existing relay behavior. Do not add a sleep-loop to the live check.
- Repository rules prohibit commits unless the user asks for them; do not commit as part of this plan without separate authorization.

## Review Focus

- Registration rejects without a registry event: all three views must publish the same failed reason and SSE must close (Task 1).
- A reply races the delivery receipt or two replies race each other: exactly one job completion and no duplicate matched IRC delivery (Tasks 2–3).
- The same `messageId` arrives from a different peer, or after cancellation/timeout: it must remain ordinary IRC traffic (Task 3).
- A worker dies, or its owner is about to park, with an open wait: cleanup must not strand a registry entry or discard a live owner (Tasks 2–3).
- Two requests from the same peer wake one subagent, or an explicit response races auto-relay: each request has its own correlation and at most one response (Task 4).
