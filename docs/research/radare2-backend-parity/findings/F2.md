## Angle
F2 radare2 project persistence: `P` commands, CLI `-p`/`-P`, storage config and env, file artifacts, reopen without binary, save/dirty semantics. All fetched 2026-11-17. Sources: radare2 git master source, official book/man, r2 tests; historical comparison tag 5.9.8 and 2017 official blog.

## Claims

### A. Command surface and exact help text
- `P?` help literal (from `help_msg_P`): `Usage: P[?.+-*cdilnsS] [file]  Project management`; `P [file] open project (formerly Po)`; `P. show current loaded project (see prj.name)`; `P+ [name] save project (same as Ps, but doesnt checks for changes)`; `P- [name] delete project`; `P* printn project script as r2 commands`; `P!([cmd]) open a shell or run command in the project directory`; `Pc close current project`; `Pd [N] diff Nth commit`; `Pi[j] [file] show project information`; `Pl list all projects`; `Pn - edit current loaded project notes using cfg.editor`; `Pn[j] manage notes associated with the project`; `Ps [file] save project (see dir.projects)`; `PS [file] save script file`; `PS* [name] print the project script file (Like P*, but requires a project)`; `Pz[ie] [zipfile] import/export r2 project in zip form (.zrp extension)`; notes: `the 'e prj.name' evar can save/open/rename/list projects`, `see the other 'e??prj.' evars`, `project are stored in dir.projects`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- No dedicated `Ps?` or `Po?` help: dispatch only prints `help_msg_P` when `input[0]=='?'`; `Ps?` is parsed as save-with-name `s?` (invalid name), `Po?` as open-with-name `o?` (invalid name). `Pn?` and `Pz?` DO have dedicated help. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- `Pn?` help literal: `Usage: Pn[j-?] [...]`; `Pn show project notes`; `Pn - edit notes with cfg.editor`; `Pn [base64] set notes text`; `Pn- delete notes`; `Pn- str delete lines matching /str/ in notes`; `Pn+ str append one line to the notes`; `Pnj show notes in base64`; `Pnj [base64] set notes in base64`; `Pnx run project note commands`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- `Pz?` help literal: `Usage: Pz[ie] ([file])`; `Pz export project to prjname.zrp`; `Pze foo.zrp export project, same as Pz`; `Pzi foo.zrp import radare2 project from given zrp file`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- Dispatch map: `P`/`Po` open (`Po` logs literal `Po is deprecated, use 'P [prjname]' instead`), `P&`/`Po&` background open, `P.` print `prj.name`, `P+`/`Ps` save, `P-` delete, `Pj`/`Pl`/`Plj` list (JSON when mode `j`), `Pi[j] [file]` info, `Pd [N]` = `git diff @~%d` in project dir (not delete), `Pc` close, `PS`/`PS*` script save/cat, `P!` shell in project dir, `P*` script to stdout. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- `Pn` is NOT project-new; it is NOTES (edits `notes.txt`). `Pi` is info. Project identity/lifecycle lives in config var `e prj.name` (`P.` prints it; `cb_prjname` open/rename/close/list; `prj.name=?` lists). Project creation = `Ps <name>` or `P+ <name>`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c (fetch 2026-11-17, primary).
- `Pi[j]` plain fields: `name:`, `path:`, `file:` (binary path parsed from rc), `current:`, `prj.new:`, `modified:` (rc.r2 mtime), `notes:`. JSON fields: `name`, `path`, `file`, `current`, `prj.new`, `modified`, `notes`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- Name rules: lowercase letters, digits, `_` only; length <64; optional trailing `.zip` accepted; absolute paths skip validation; master also rejects names failing `r_str_filter_file`. `P-` refuses paths outside `dir.projects` (`Refusing to delete project outside dir.projects`); save refuses overwriting a different existing project (`A project with this name already exists. Use P-%s to delete it`). Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).

### B. CLI `r2 -p` / `-P`
- `r2 -h` literal: `-p [prj]     use project, list if no arg, load if no file`; `-P [file]    apply rapatch file and quit`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/main/radare2.c (fetch 2026-11-17, primary).
- Bare `r2 -p` (`argc==2`) calls `r_core_project_list(r, 0)` and exits; `-p ?` does the same. `r2 -p .` does NOT list: `.` becomes project name, fails name validation, CLI logs `Cannot find project`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/main/radare2.c and https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- Project open happens after rc-file parsing: comment literal `// open the project after the rc files so prj.sandbox and dir.projects are honored`; failure logs `Cannot find project`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/main/radare2.c (fetch 2026-11-17, primary).
- With no file argument and `-p name`, CLI derives pfile via `r_core_project_name()` then calls `r_core_file_open()`; explicit binary argument is not required by the project commands. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/main/radare2.c and https://book.rada.re/projects/usage.html (fetch 2026-11-17, primary).
- Man page: `.It Fl p Ar prj Set project file`; `.It Fl P Ar file Apply rapatch file and quit`; binary projects with `RPRJ` header passed as a file restore via `prj open`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/man/radare2.1 (fetch 2026-11-17, primary).
- Tests prove per-process override order: `radare2 -q -p sandboxed` honors `dir.projects`/`prj.sandbox` from `R2_RCFILE`; adding `-e dir.projects=scripts` overrides it (`notfound`). Source: https://raw.githubusercontent.com/radareorg/radare2/master/test/db/tools/r2 (fetch 2026-11-17, primary).

### C. Storage location and config
- `dir.projects` default = `r_xdg_datadir("projects")` = `$XDG_DATA_HOME/radare2/projects`, else `<home>/.local/share/radare2/projects`. Callback `cb_dir_projects` converts value to absolute path. Official book prints `~/.local/share/radare2/projects` (tilde form). Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/util/xdg.c , https://book.rada.re/projects/usage.html (fetch 2026-11-17, primary).
- Per-process override: `e dir.projects=/abs/path` (or `r2 -e dir.projects=...` before `-p`), or set `XDG_DATA_HOME` before process start, or `R2_RCFILE`. Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/util/xdg.c , https://raw.githubusercontent.com/radareorg/radare2/master/test/db/tools/r2 (fetch 2026-11-17, primary).
- `R2_PROJECTS`: no match in `libr/core/cconfig.c`, `libr/main/radare2.c`, man page, or official book (grep/fetch 2026-11-17) => unverified; no such environment variable in current master. Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/main/radare2.c , https://raw.githubusercontent.com/radareorg/radare2/master/man/radare2.1 , https://book.rada.re/config/files.html (fetch 2026-11-17, primary for absence-by-source-review).
- `prj.*` defaults in master: `prj.name=""`, `prj.new=false`, `prj.files=false`, `prj.vc=true`, `prj.zip=false`, `prj.gpg=false` (`TODO: encrypt project with GnuPGv2`), `prj.history=false`, `prj.sandbox=false`, `prj.abspath=true`, `prj.prompt=false`, `prj.vc.message=""`, `prj.vc.type=git` (rvc on non-git build). Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c (fetch 2026-11-17, primary).
- `prj.abspath=true`: `o*` output converts desc URI to absolute path unless it contains `://`; when `prj.files` and `prj.name` are set, `o*` instead emits `pushd <dir.projects>/<prj.name>` / `o <basename>` / `popd`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_open.inc.c (fetch 2026-11-17, primary).
- `e prj.name = X` setter can open/rename/close/load-list project via `cb_prjname`; `prj.name=?` lists projects. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c (fetch 2026-11-17, primary).

### D. Files produced
- Layout: `<dir.projects>/<name>/rc.r2`, first line exactly `# r2 rdb project file`; project detected by that file or by `<name>.d` directory; save writes via `r_file_dump`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- `project_save_script(..., R_CORE_PRJ_ALL=0xFFFF)` writes: `# eval` (`r_config_list(config,NULL,'r')`), `o*` + `om*` + `o=<fd>`, `tcc*`, `# functions` + `fs functions` + `afl*`, `# registers` + `ar*` + `arR`, `# flags` + flag list + `fz*`, `# meta` + `r_meta_print_list_all(...,R_META_TYPE_ANY,1,...)` + `fv*` + `ano*@@@F`, `ax*`, `f.**`, `db*`, `ah*`, `# types` + `t*`, `# classes` + `acl*`, `# macros` + `(*`, `# aliases` + `$*`, `wc*`, `fs <current>`, `# seek` + `s 0x%08llx`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c and https://raw.githubusercontent.com/radareorg/radare2/master/libr/include/r_core.h (fetch 2026-11-17, primary).
- Optional `prj.bin`: saved when `prj.new=true` via `prj save <prj_dir>/prj.bin`; load tries `prj load <prj_dir>/prj.bin` first; man page describes `RPRJ` binary projects. Optional `bin/<basename>` copy when `prj.files=true`; `notes.txt` via `Pn`; `history` file when `prj.history=true`; `.git` when `prj.vc=true`; `<name>.zrp` via `Pz`/`Pze`. Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c , https://raw.githubusercontent.com/radareorg/radare2/master/man/radare2.1 (fetch 2026-11-17, primary).
- 5.9.8 still wrote sdb files: `sdb_file(ns->sdb, <prj_dir>/rop.d/<ns>); sdb_sync(...)`; 2017 official blog says project = `rc` + `.sdb` files. Master save path has no sdb writes (grep 2026-11-17). Sources: https://raw.githubusercontent.com/radareorg/radare2/5.9.8/libr/core/project.c and https://radareorg.github.io/blog/posts/project-files/ and https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17; 5.9.8/blog primary but historical).

### E. Reopen without source binary
- Official book: `P my_project` and `r2 -p my_project` — `There is no need to specify the file associated with the project` / `reopen the project without specifying the binary file associated with it`. Source: https://book.rada.re/projects/usage.html (fetch 2026-11-17, primary).
- Mechanism: rc.r2 stores binary path in first `o "..."` line; `r_core_project_file()` extracts until next `"`, decoding `base64:` prefix with `sdb_decode`. No hash/checksum stored: grep for `hash|sha|md5|crc` in master `project.c` = no matches. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- Default `prj.files=false` (cconfig.c): `Po`/`P` stores only the binary path (`o ...`) and requires the original file to still exist; `prj.files=true` copies the binary into `<project>/bin/<basename>` and rc uses `pushd`/`popd` + basename. Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_open.inc.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- Missing binary at stored path: exact error `File associated with the project is missing: %s`; if `prj.prompt=true` and interactive, prompt literal `New path for '%s': ` and rewrite the `o "..."` line. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- `prj.sandbox=true`: project script executed via `r_sandbox_run`, `o` lines and `'e prj.name = ` lines stripped to reuse current binary; with no open desc logs `Open a binary before loading a sandboxed project`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- CLI no-file path with `-p`: `mr.pfile = r_core_project_name(r, mr.project_name)` then `r_core_file_open()`; `Cannot find project file` logged only when name resolution returned NULL. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/main/radare2.c (fetch 2026-11-17, primary).
- Save preconditions: `radare2 does not support projects on debugged bins` when `cfg.debug=true`; `Open a binary before saving a project` when no IO desc. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).

### F. Save / dirty / undo semantics
- `P+` and `Ps` both call `r_core_project_save(core, file)`; if no arg, file falls back to current `prj.name`; with neither, `Use: Ps [projectname]` and return code 1. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- Saved mutations: function defs (`afl*`), function folds (`afF`, test confirms), comments (`CCu base64:...`, test confirms), types (`t*`), xrefs (`ax*`), analysis hints (`ah*`), flags (`f*`), breakpoints (`db*`), config/eval changes, seek, IO maps. Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c and https://raw.githubusercontent.com/radareorg/radare2/master/test/db/cmd/projects (fetch 2026-11-17, primary).
- Success calls `r_core_project_undirty`: sets `core->config->is_dirty=false`, `core->anal->is_dirty=false`, `core->flags->is_dirty=false`. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- `r_core_project_is_dirty()` literally returns `!R_DIRTY_CHECK(config) && !R_DIRTY_CHECK(anal) && !R_DIRTY_CHECK(flags)`, macro `R_DIRTY_CHECK(x) == (x)->is_dirty` => returns TRUE when all three are CLEAN (name inverted); CLI uses `if (r_core_project_is_dirty && !prj.alwaysprompt) break;` = skip save prompt when clean. Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c , https://raw.githubusercontent.com/radareorg/radare2/master/libr/include/r_types_base.h , https://raw.githubusercontent.com/radareorg/radare2/master/libr/main/radare2.c (fetch 2026-11-17, primary).
- `r_core_project_is_dirty()` / `r_core_project_undirty()` are C APIs only; no `P` command exposes dirty state (`P?` has no dirty verb; `Pi` reports `modified` mtime, not a dirty bit). Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c and https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c (fetch 2026-11-17, primary).
- `Pi` `modified` = `st_mtime` of `rc.r2`, not a dirty bit. Source: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).
- Undo/redo: core has `ucu` (undo previous action), `ucd` (redo action), `uc-` (undo last action) under `uc` (see `e cmd.undo`); project history is git commits via `prj.vc` and `Pd [N]` diff. No project-level undo/redo command in `P` namespace. Sources: https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd.c and https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c (fetch 2026-11-17, primary).

## Gaps
- `R2_PROJECTS`: unverified; no primary occurrence. Use `dir.projects` / `XDG_DATA_HOME` instead.
- No runtime test of missing-binary reopen in this angle; behavior quoted from source only.
- `Ps?` / `Po?` have no dedicated help text; `P?` is canonical.
- No project-level undo/redo; git versioning + `uc*` are the closest mechanisms.
- Master vs 5.9.8/2017 file-format divergence not pinned to an exact release boundary; treat `rc.r2` as the portable artifact.
- Binary-project (`RPRJ`, `prj.bin`, `prj load/save`) internal format not inspected; only existence/loading path verified from man + project.c.
