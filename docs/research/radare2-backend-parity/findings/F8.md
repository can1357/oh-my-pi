## Conflicting evidence

- **`pdc` book vs master — verdict: BOTH correct, version skew; runtime binary wins for "what 6.2.2 emits".** The official book says no control-flow improvement and its example uses `goto`/labels. Master `plugin.c` defaults `pdc.structured=true` (plus `optimize`/`inline`), so master *does* structure by default. The locally shipped 6.2.2 binary has `pdc.structured=false`, no `pdc.optimize`/`pdc.inline` keys at all, and emits `if (!v) goto loc_...` + `loc_0x...:` labels. Therefore the book accurately describes **default shipped 6.2.2 behavior**, and master source describes **newer post-6.2.2 behavior** (built 2026-10-03; master read 2026-11-17). The book is not "wrong" and master is not "wrong" — they target different code states. For backend parity against the installed 6.2.2 binary, design for goto/labels by default and treat `pdc.structured=true` as an experimental opt-in. F4's one-line "Trust source" is too strong for this specific question.
- F5's "all claims source-only, no runtime binary executed" is now closed for `afn`, `CC`/`CCj`, `af+`, `afs`, `af`, and `axtj`: all matched source-derived claims. The `af+ <addr> <size> <name>` draft form is definitively wrong (second token is name, size stays 0).
- F5's `Pi j` JSON fields remain source-only: the literal `Pi j` invocation is not a valid way to read them in 6.2.2 (`ERROR: Unknown project 'j'`), and `Pi`/`Pij` require a project name. Runtime shape unverified; not guessed.
- F5 predicted `afs` custom-type rejection (issue #17432) but builtin types work; quoted signatures fail with `ERROR: at line 1: Cannot find ( in function definition`. This error text was predicted as unknown; now captured.
- `aflj~{.name}` from F3's search list prints only `entry0` on this binary; do not use it as a complete function-name enumeration.
