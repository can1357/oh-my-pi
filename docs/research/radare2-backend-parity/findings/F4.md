## Angle
F4 — pseudocode/decompilation for radare2 backend parity. Scope: `pdc`, `pdg` (r2ghidra), `pdd` (r2dec), structured JSON, address mapping, analysis prerequisites, failure modes.

## Claims

### pdc — bundled pseudo-decompiler

- Only `pdc` pseudodecompiler ships inside radare2; `pdg` and `pdd` are external plugins installed with `r2pm`. — https://book.rada.re/arch/decompile.html — 2026-11-17 — primary
- `pdc` combines ESIL emulation, `asm.pseudo` disassembly, reference processing, function signature, comments and metadata. Book states no control-flow improvement (switch/if/else/for/while), no optimization, no garbage removal; output verbose/noisy, handy/fast, good LLM input. Available for ALL r2 architectures. — https://book.rada.re/arch/decompile.html — 2026-11-17 — primary
- Source: `pdc` is a core plugin `.command = "pd:c"`, `.name = "pseudo"` in `libr/core/p/pseudo/plugin.c`. Exact help: `Usage: pd:c[acjlot*]  experimental, unreliable and hacky pseudo-decompiler`; `pd:c` pseudo decompile function in current offset; `pd:c*` emit decompiled lines as CCu comment commands; `pd:ca` side by side comparing assembly and pseudo; `pd:cc` pseudo-decompile with C helpers around; `pd:cl` linear pseudo-decompilation scrolling across functions; `pd:co` show associated offset next to pseudecompiled output; `pd:cj` in json format for codemeta annotations (used by frontends like iaito); `pd:ct` dump the structuring region AST (decompiler debug). Invoked as `pdc`, `pdcj`, etc. — https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/p/pseudo/plugin.c — 2026-11-17 — primary
- Config vars (defaults): `pdc.structured=true` ("emit structured if/else instead of goto in pdc"), `pdc.trycatch=true`, `pdc.optimize=true` ("simplify register expressions and remove dead assignments in pdc"), `pdc.inline=false`. — https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/p/pseudo/plugin.c — 2026-11-17 — primary
- `pdcj` source shape: top-level `"code"` (string) + `"annotations"` (array of `{"start": <char index>, "end": <char index>, "offset": <address>, "type": "offset"}`). `annotate_offset()` emits exactly `start`, `end`, `offset`, `type`. Help confirms JSON is "for codemeta annotations (used by frontends like iaito)". — https://raw.githubusercontent.com/radareorg/radare2/17467b7b9794ddc07fbab35cde2697cb7b515250/libr/core/p/pseudo/pseudo.c and https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/p/pseudo/plugin.c — 2026-11-17 — primary
- `pdc` requires a function at current offset. Failure path logs `Cannot find function in 0x%08` and returns false. — https://raw.githubusercontent.com/radareorg/radare2/17467b7b9794ddc07fbab35cde2697cb7b515250/libr/core/p/pseudo/pseudo.c — 2026-11-17 — primary
- Internals: forces `asm.pseudo=true`, `asm.decode=false`, `asm.emu=true`, `emu.str=true`, `emu.write=true`, `asm.syntax=intel`, `io.cache=true`, `asm.cmt.col=30`, runs `aeim`, emulates blocks in CFG order, then restores all held config. — https://raw.githubusercontent.com/radareorg/radare2/17467b7b9794ddc07fbab35cde2697cb7b515250/libr/core/p/pseudo/pseudo.c — 2026-11-17 — primary
- Address mapping: `pdco` prints offset column; `pdca` two-column asm vs pseudo; `pdc*` emits CCu comment commands; `pdcj` annotations give char-range to address. — https://book.rada.re/arch/decompile.html and https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/p/pseudo/plugin.c — 2026-11-17 — primary

### pdg — r2ghidra, NOT bundled

- r2ghidra = native C++ integration of Ghidra decompiler; Ghidra itself/Java not required, built self-contained from ghidra-native. — https://github.com/radareorg/r2ghidra — 2026-11-17 — primary
- Exact `pdg?` help (README, mirrored in `src/core_ghidra.cpp`): `pdg` decompile current function; `pdg*` decompiled code returned to r2 as comment; `pdga` side by side two column disasm and decompilation; `pdgd` dump debug XML; `pdgj` dump current decompiled function as JSON; `pdgo` side by side with offsets; `pdgp` switch to RAsm/RAnal plugins driven by SLEIGH; `pdgs` display loaded Sleigh languages; `pdgsd N` disassemble N instructions with Sleigh and print pcode; `pdgss` display auto-matched Sleigh Language ID; `pdgt` dump Ghidra structured control-flow tree; `pdgtj` dump that tree as JSON; `pdgw` write recovered variable types, names and signatures to r2; `pdgx` dump XML of current decompiled function. — https://github.com/radareorg/r2ghidra and https://raw.githubusercontent.com/radareorg/r2ghidra/df21ab245c186ca3075c98e8abe5d266293a5c23/src/core_ghidra.cpp — 2026-11-17 — primary
- Install path: `r2pm -U`, `r2pm -ci r2ghidra`; `-g` for system-wide. Build deps: radare2 + dev headers, pkg-config, acr/make or meson/ninja, C++ compiler, git/python3. Manual ACR: `./preconfigure`, `./configure` with r2 prefix, `make`, `make install` or `make user-install`. Meson: `meson setup b`, `meson compile -C b`, `meson install -C b`. Official r2pm db entry exists (`db/r2ghidra`), with source build, binary zip hook, Windows hooks, and `R2PM_DEPS r2ghidra-sleigh`. Plugin is NOT in radare2 core. — https://github.com/radareorg/r2ghidra and https://raw.githubusercontent.com/radareorg/radare2-pm/master/db/r2ghidra — 2026-11-17 — primary
- Portability: Termux Android-arm64, macOS/iOS, GNU/Linux, Windows, FreeBSD/x86-64. Architecture coverage = installed Sleigh languages (`pdgs`); `e r2ghidra.lang` overrides auto-detection, `e r2ghidra.sleighhome` points to SLA/LSPEC files. Aliases still need matching Sleigh files (e.g. `sh` needs optional SuperH4, not bundled SuperH). Plugin leaves `cpus` unset so `e asm.cpu=?` is empty. — https://github.com/radareorg/r2ghidra — 2026-11-17 — primary
- Prerequisite: README says `af` first, then `pdg`. Source: `r_anal_get_fcn_in(core->anal, addr, R_ANAL_FCN_TYPE_NULL)`; if none, throws `LowlevelError("No function at this offset")`. Full `aaa` not strictly required — only a function at seek address. — https://github.com/radareorg/r2ghidra and https://raw.githubusercontent.com/radareorg/r2ghidra/df21ab245c186ca3075c98e8abe5d266293a5c23/src/core_ghidra.cpp — 2026-11-17 — primary
- Timeout: `e r2ghidra.timeout` default 0 (off). On UNIX with value > 0, plugin forks child, pipes output, polls until deadline, prints `Timeout`, sends SIGKILL, then reports `Decompiler process died unexpectedly` if child did not exit cleanly. First run slower; fork loses cache. `pdgw` bypasses fork because writes go into r2 DB. Outside UNIX: warning `r2ghidra.timeout is not supported outside UNIX systems.` — https://raw.githubusercontent.com/radareorg/r2ghidra/df21ab245c186ca3075c98e8abe5d266293a5c23/src/core_ghidra.cpp — 2026-11-17 — primary
- `pdgj` structured JSON: built by radare2 shared `r_codemeta_print_json`, so `{"code": "<text>", "annotations": [ ... ]}`. Annotation items: `{"start": n, "end": n, "type": "offset", "offset": n}`, `"function_name"` (+`name`, `offset`), `"global_variable"` (+`offset`), `"constant_variable"` (+`offset`), `"local_variable"` (+`name`), `"function_parameter"` (+`name`), `"syntax_highlight"` (+`syntax_highlight` subtype). r2ghidra appends `"pcode_ops": [{"space","offset","uniq","opcode","is_dead"}]`; with `e r2ghidra.deadcode=true` also `"eliminated_ops"`. On error in JSON modes: `{"errors":["Ghidra Decompiler Error: ..."]}`. — https://raw.githubusercontent.com/radareorg/radare2/master/libr/anal/codemeta.c and https://raw.githubusercontent.com/radareorg/r2ghidra/df21ab245c186ca3075c98e8abe5d266293a5c23/src/core_ghidra.cpp — 2026-11-17 — primary
- Structured JSON carries variable NAMES but no variable TYPES: `RCodeMetaItem.variable` has only `char *name`; JSON printer emits `name` only. Types live in `code` text; `pdgw` writes recovered names, types and signature back into r2. `pcode_ops` gives opcode numbers, not C types. — https://raw.githubusercontent.com/radareorg/radare2/master/libr/include/r_codemeta.h and https://raw.githubusercontent.com/radareorg/radare2/master/libr/anal/codemeta.c and https://github.com/radareorg/r2ghidra — 2026-11-17 — primary
- Address mapping back to r2: `pdgo` prints offset per line; `pdg*` emits CCu comments; `pdgj` offset annotations + pcode_op `space`/`offset`; `pdgtj` tree nodes have `type`, `index`, `children`; basic-block leaves have `space`, `start`, `stop` (stop = last instruction address, not byte after). Indices repeat across nesting; not unique node IDs. — https://github.com/radareorg/r2ghidra — 2026-11-17 — primary
- Other failure modes: `LowlevelError` produces `Ghidra Decompiler Error: ...`; `Function not fully decompiled. No structure present.` for `pdgt`/`pdgtj` on incomplete analysis; tree exceeding JSON depth returns error while `pdgt` still prints; `e r2ghidra.vars` "may cause segfaults if enabled" per book config list; `r2ghidra.verbose` surfaces Ghidra warnings. — https://raw.githubusercontent.com/radareorg/r2ghidra/df21ab245c186ca3075c98e8abe5d266293a5c23/src/core_ghidra.cpp and https://book.rada.re/arch/decompile.html — 2026-11-17 — primary
- Quality caveat: r2ghidra output differs from standalone Ghidra because r2 analysis results differ; structures and complex features may be missed. — https://book.rada.re/arch/decompile.html — 2026-11-17 — primary
- With r2 ABI 163 or newer, `pdg` inlines analyzed callees marked `inline` when `e r2ghidra.inline=true` (default); `afia+ inline @ child` marks callee, `e r2ghidra.inline=false` disables. — https://github.com/radareorg/r2ghidra — 2026-11-17 — primary

### pdd — r2dec, NOT bundled

- r2dec is a separate QuickJS/JavaScript plugin (`wargio/r2dec-js`), installed via `r2pm -U` then `r2pm -i r2dec`; manual `meson setup build` + `ninja -C build install`. Official r2pm db entry `db/r2dec` installs `libcore_pdd` plugin. NOT bundled with radare2. — https://github.com/wargio/r2dec-js and https://raw.githubusercontent.com/radareorg/radare2-pm/master/db/r2dec — 2026-11-17 — primary
- `pdd?` exact help from current source `c/r2dec-plugin.c`: `Usage: pdd[*tcabojAfi]`; `pdd` decompile current function; `pddt` list supported architectures; `pdd*` decompiled code returned to r2 as comment via CCu; `pddc` code returned as "file:line code" via CL; `pdda` side by side assembly; `pddb` scopes only; `pddo` side by side with offsets; `pddj` decompile as json; `pddA` annotation output; `pddf` decompile all functions; `pddi` generate issue data. Source switch confirms flags map to `--as-json`, `--annotation`, `--as-code-line`, `--all-functions`. — https://raw.githubusercontent.com/wargio/r2dec-js/master/c/r2dec-plugin.c — 2026-11-17 — primary
- Prerequisite: README says analyze function (`af`) then run `pdd`. Failure from JS: `Error: no data available.` / `Please analyze the function/binary first.` when graph empty. Supported arch list includes x86/x64, arm 16/32/64, mips, ppc 32/64, dalvik, sparc, avr, wasm, riscv, 6502, 8051, bpf, m68k, sbf, sh, stm8, v850, nds32 (several experimental). — https://github.com/wargio/r2dec-js and https://raw.githubusercontent.com/wargio/r2dec-js/master/js/r2dec-plugin.js — 2026-11-17 — primary
- `pddj` JSON is r2dec-specific, NOT RCodeMeta: `{"lines":[...],"errors":[...],"log":[...]}` from `js/libdec/printer.js`. `pddA` produces `{"code":"...","annotations":[...]}` with items `{start,end,type,name?,offset?}`; `offset` is a STRING there (`this.location.toString()`), and types include function_name, function_parameter, local_variable, constant_variable, offset, syntax_highlight. — https://raw.githubusercontent.com/wargio/r2dec-js/master/js/libdec/printer.js and https://raw.githubusercontent.com/wargio/r2dec-js/master/js/libdec/annotation.js — 2026-11-17 — primary
- Status: active upstream (614 stars, 36 open issues, CI workflows present, 2026 copyright in source); external plugin, needs separate install, no timeout flag found in plugin source. — https://github.com/wargio/r2dec-js and https://raw.githubusercontent.com/wargio/r2dec-js/master/c/r2dec-plugin.c — 2026-11-17 — primary

### Recommended backend choice

- Default to `pdcj`: bundled, zero plugin dependency, works all architectures, gives `code` plus `annotations` with numeric char ranges and address `offset`; also `pdco`/`pdc*` for offset display and comment injection. Offer `pdgj` when r2ghidra installed and Sleigh language exists: richer annotations (function/local/param names, pcode ops, `pdgtj` CFG tree), higher-quality C, plus `r2ghidra.timeout` for cancellation. Do not depend on `pdd`; it is external, has a different JSON shape, and no timeout. — derived from primary facts above — 2026-11-17 — speculative (design choice)
- Do NOT design against `e decompiler.plugin` / `decompiler.*` config: GitHub discussion #24070 is an Idea with all port checkboxes unchecked; maintainer reply says idea was considered years ago but not implemented; current per-plugin commands (`pdc`/`pdg`/`pdd`) remain the interface. — https://github.com/radareorg/radare2/discussions/24070 — 2026-11-17 — primary
- Common decompiler subcommand convention from book: `pdgo/pddo/pdco` = per-line offsets; `pdga/pdda/pdca` = two-column asm vs decompilation; `pdgj/pddj/pdcj` = JSON. — https://book.rada.re/arch/decompile.html — 2026-11-17 — primary

## Conflicting evidence

- Book: `pdc` "does not implement any control flow improvement (like switch, if/else, for/while)". Current master source has `pdc.structured=true` by default and `pdc.optimize=true`, emitting structured if/else and simplifying expressions. Likely version skew (book text predates 6.2.x restructuring). Use source for current behavior; book for design intent. — https://book.rada.re/arch/decompile.html and https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/p/pseudo/plugin.c — 2026-11-17 — primary
- r2dec README help omits `pddj`, `pddA`, `pddc`, `pddt`, `pddf`; current `c/r2dec-plugin.c` implements all of them. Trust source. — https://github.com/wargio/r2dec-js and https://raw.githubusercontent.com/wargio/r2dec-js/master/c/r2dec-plugin.c — 2026-11-17 — primary
- Book lumps `pdgj/pddj/pdcj` as "json output"; actual shapes differ: `pdgj` = radare2 RCodeMeta (`code`+`annotations` numeric offsets) plus pcode ops; `pdcj` = its own `annotations` array of numeric `start/end/offset` + `code` (same field names, hand-built); `pddj` = r2dec-specific `lines/errors/log`; `pddA` = r2dec-specific `code/annotations` with string offsets. — sources listed above — 2026-11-17 — primary
- Discussion #24070 shows `decompiler.plugin` and `decompiler.r2ghidra.*` vars as a proposal only; no evidence they exist in released radare2. Treat as not available. — https://github.com/radareorg/radare2/discussions/24070 — 2026-11-17 — primary
