## Claims

### 1. Decompiler: core has only pseudo-decompiler; real decompilers are optional plugins

- FACT: "By default only the `pdc` pseudodecompiler is shipped within radare2, but you can install any other via `r2pm`" — https://book.rada.re/arch/decompile.html — 2026-11-17 — primary.
- FACT: `pdc` is NOT a real decompiler: "It is not really implementing any control flow improvement (like switch, if/else, for/while). Also, no code optimizations or garbage logic is removed." Output "full of goto and label statements"; "available for ALL architectures supported by r2". Same URL — primary.
- FACT: `pdg` = r2ghidra, `pdd` = r2dec; both are `pd` subcommands installed via `r2pm` (`r2pm -U; r2pm -ci r2ghidra`). https://book.rada.re/arch/decompile.html + https://github.com/radareorg/radare2/blob/master/README.md ("r2ghidra ... accessible with `pdg`") + https://github.com/radareorg/r2ghidra/blob/master/README.md — 2026-11-17 — primary.
- FACT: book warns r2ghidra output ≠ Ghidra: "r2ghidra is not providing the same analysis results that Ghidra would provide ... probably miss quite a lot of details when handling structures and other complex features." https://book.rada.re/arch/decompile.html — primary.
- FACT (what breaks if absent): `pdg`/`pdd` are plugin-provided; without them no C decompilation exists, only `pdc` pseudo-C. Even installed, setup can fail: issue #21 "Ghidra Decompiler Error: No print languages registered" / "No languages available, make sure r2ghidra.sleighhome is set correctly!" — https://github.com/radareorg/r2ghidra/issues/21 (maintainer @trufae confirms build/install incompatibility) — 2026-11-17 — primary.
- CLOSEST ALTERNATIVES (exact): `pdc` / `pdcj` / `pdco` / `pdca` (always available); if plugin present `pdg`, `pdgj`, `pdgo`, `pdga`, `pdgw` (writes recovered types/names back to r2), `pdgt`/`pdgtj` (control-flow tree). https://github.com/radareorg/r2ghidra/blob/master/README.md — primary.
- CANCEL HOOK for decompile: `e r2ghidra.timeout=N` — "Run decompilation in a separate process and kill it after a specific time". Same README — primary.

### 2a. Repeatable comments: no repeatable flag exists

- FACT: full official `C?` help has `CC[?] [-] [comment-text] [@addr]` add/remove, `CC!` editor, `CC.[addr]`, `CCa[-at]|[at] [text]`, `CCu [comment-text] [@addr]` add **unique** comment, `CC,`-style file link. **No `CCr`, no repeat flag, no xref-propagating comment option.** The only `repeat` token in help is `Cd[-] [size] [repeat] [@addr]` (data-array repetition, unrelated). https://book.rada.re/arch/metadata.html — 2026-11-17 — primary.
- Absence is from complete official command help (not inference from partial docs) — confidence primary for "no documented repeatable-comment command"; speculative that no hidden internal API exists.
- CLOSEST ALTERNATIVES (exact): emit one `CC <text> @ <addr>` per target address (loop results of `axt`/`axf`); or `CCu <text> @ <addr>` for a comment guaranteed unique per address; long text via `CC,` file link. Same URL — primary.

### 2b. set_type (C declaration): equivalents DO exist — assumption "no direct equivalent" is WRONG

- FACT: `afs[!] ([fcnsign])` = "get/set function signature at current address"; `afsr [function_name] [new_type]` = change function type; `td <string>` = load type from C declaration string; `to <path>` = load C header; `tl <type> = <addr>` = link type to address (stored in SDB); `CF[sz] [fcn-sign..] [@addr]` = function-signature annotation. https://book.rada.re/analysis/code_analysis.html + https://book.rada.re/analysis/types.html + https://book.rada.re/arch/metadata.html — 2026-11-17 — primary.
- FACT (awkwardness): `afs` C-parser rejects custom types. Issue #17432: `afs Mammal *entry0 (int64_t arg3);` → "<string>:1: error: ';' expected (got \"entry0\")". Maintainer @XVilka: "It allows only the types that are predefined at this stage, i.e. known to the compiler." Issue still OPEN. https://github.com/radareorg/radare2/issues/17432 — 2026-11-17 — primary.
- FACT (awkwardness): atomic types are r2-specific (`int8_t`/`uint64_t`), not C standard; `int` is rewritten to `int32_t`/`int64_t` per platform. Types need quoting through r2pipe because declarations contain spaces (`"td struct foo {char* a; int b;}"`). https://book.rada.re/analysis/types.html — primary.
- FACT: `Ct <comment>` is only a **type analysis comment**, not a real type (help: "add/remove type analysis comment"); `Cf` "doesn't change analysis results. It is only a visual boon." https://book.rada.re/arch/metadata.html — primary.
- CLOSEST ALTERNATIVE (exact): define with `td "<C decl>"`, link with `tl <type> = <addr>`; for function signatures use `afs "<sig>"` (builtin types only) or `pdgw` (r2ghidra writes recovered types/signatures); propagate offsets with `aat` after `tl`. Same sources — primary.

### 3a. Dirty tracking: C API EXISTS (shared assumption wrong), but NO command-level read

- FACT: `libr/core/project.c` defines `R_API bool r_core_project_is_dirty(RCore *core)` = `!R_DIRTY_CHECK(core->config) && !R_DIRTY_CHECK(core->anal) && !R_DIRTY_CHECK(core->flags)` and `r_core_project_undirty()`; called after successful save/open. https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c — 2026-11-17 — primary.
- FACT: no `P` subcommand exposes dirty state. Official `P?` help lists only `P`, `P.`, `P+`, `P-`, `P*`, `P!`, `Pc`, `Pd`, `Pi`, `Pl`, `Pn`, `Ps`, `PS`, `PS*`, `Pz`; note says `e prj.name` can save/open/rename/list. `Pn` is **notes**, not "name". https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c + https://book.rada.re/projects/usage.html — primary.
- FACT: help claims `P+` "save project (same as Ps, but doesnt checks for changes)", but implementation is `case '+': // "P+" // xxx` falling through into `case 's': // "Ps"` — identical save path. Change-check is not implemented in current source code path. Same cmd_project.inc.c:417-435 — primary.
- CLOSEST ALTERNATIVES (exact): track dirty in the NDJSON layer (set true on any rename/comment/type/make_function, false after `Ps`/`P+`); or read `e prj.name` for loaded-project identity and `Pi`/`Pnj` for persisted state. No r2 command gives a boolean dirty flag — primary (absence verified against complete help + source).

### 3b. Cancellation / async in r2pipe: nuanced, not "none"

- FACT: Python r2pipe has THREE backends: `open_sync.py`, `open_async.py`, plus HTTP/TCP/native (README table Python row shows `async X`). https://github.com/radareorg/radare2-r2pipe/blob/master/README.md — 2026-11-17 — primary.
- FACT (sync has no timeout/cancel): `open_sync.py` `_cmd_process()` writes `cmd + "\n"`, then loops `r.read(4096)` until NUL terminator; no timeout, no signal handling, no cancel. Only failure path: `if self.process.poll() is not None: raise RuntimeError("Process terminated unexpectedly...")`. Commands held under `threading.Lock`. https://github.com/radareorg/radare2-r2pipe/blob/master/python/r2pipe/open_sync.py — primary.
- FACT (async explicitly refuses per-command cancel): `open_async.py` `_command()` uses `await asyncio.shield(task)` with comment "A canceled caller must not interrupt reading a command's response." `_execute_cmd_with_lock()` serializes all commands under `self._cmd_lock`; `aclose()` gathers in-flight commands then `_close_process()` does `process.terminate()`, waits 1.0s, then `process.kill()`. Process-mode `_cmd_process()` has NO `wait_for` timeout; HTTP/TCP modes use `asyncio.wait_for(..., timeout=10.0/5.0/1.0)`. https://github.com/radareorg/radare2-r2pipe/blob/master/python/r2pipe/open_async.py — primary.
- IMPLICATION (speculative, derived from code, not a documented guarantee): cancelling a long sync command by killing the r2 process discards the whole analysis session and leaves the NUL-framed stream unusable; there is no checkpoint/resume at command granularity beyond the project file.
- CLOSEST ALTERNATIVES (exact): use `open_async()` + `aclose()`/`process.terminate()` as hard cancel (session lost); bound work at the r2 level with `e r2ghidra.timeout=N`, `e anal.timeout` (unverified — do not rely) or smaller analysis batches (`afl @ ...`, `pd N`); HTTP/TCP backends have transport read timeouts.
- FACT: r2 itself installs a SIGINT handler in main console context (`r_sys_signal(SIGINT, __break_signal)` guarded by `r_cons_context_is_main(cons, context)`), so embedded/r2pipe contexts are explicitly treated differently — https://github.com/radareorg/radare2/commit/7402b04 — primary but not a documented r2pipe cancellation contract.

### 4. Project reopen: original binary still required by default (but docs oversimplify)

- FACT: project save writes an `o "<path>"` line via `o*` into `rc.r2`; load extracts it with `r_core_project_file()` and checks existence: `R_LOG_ERROR ("File associated with the project is missing: %s", prj_file)`. With `prj.prompt=false` (default) no re-path prompt in headless use. https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c — 2026-11-17 — primary.
- FACT: `prj.files` default **false** — `SETB("prj.files", "false", "save the target binary inside the project directory")`; `prj.new` default false; `prj.prompt` default false. https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c — primary. So default = store path only → binary must still exist at that absolute path.
- FACT: `base64:` prefix in the `o` line is decoded (in-memory blobs supported); `prj.files=true` copies the binary into `<project>/bin/`; `prj.new=true` writes `prj.bin`. Same project.c — primary.
- FACT: "obsolete safe" path: project can be zipped with `Pze foo.zrp` / imported `Pzi foo.zrp`; zip uses EXTERNAL `zip`/`unzip` binaries via `r_sys_cmdf` with source comment "XXX use the ZIP api instead!" — https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cmd_project.inc.c — primary / awkward dependency.
- CLOSEST ALTERNATIVES (exact): before `Ps`, set `e prj.files=true` (and optionally `e prj.new=true`) so the binary is copied; use `Pze`/`Pzi` for portable handoff; on missing path set `e prj.prompt=true` only works with `scr.interactive=true`, otherwise pass a fresh binary to `r2pipe.open(path)` and apply saved `P*`/`PS*` script.

### 5. JSON coverage / output artifacts

- FACT: `cmdj()` is only as good as the command's `j` variant; r2pipe README: "As long as the output can be tricky to parse, it's recommended to use the JSON output" — implies text output is not machine-safe. https://github.com/radareorg/radare2-r2pipe/blob/master/README.md — 2026-11-17 — primary.
- FACT (real breakage): `aflj` emitted invalid JSON `{"ratbbins": -nan}` which "prevents the JSON string from being serialized using the r2pipe.python cmdj() function" (issue #23471); maintainer @trufae fixed in PR #23472. https://github.com/radareorg/radare2/issues/23471 — 2026-11-17 — primary. Design consequence: `cmdj` must tolerate parse failure (r2pipe async `_json_command` catches `ValueError/KeyError/TypeError`, prints `r2pipe.cmdj.Error`, returns None).
- FACT (coverage uneven historically): issue #7339 "`afll` needs a JSON output" — "`afllj` returns the same string as `afll`"; @radare: "We should do the afllj", later "I would prefer a single aflj". Closed 2018; do NOT assume current status without checking current source. https://github.com/radareorg/radare2/issues/7339 — primary (historical).
- FACT (color/escape artifacts): `e scr.color` defaults to 1 ("ansi") with modes 0/1/2/3; `scr.color.pipe=false` but `scr.color.grep`, `scr.color.ops`, `scr.color.args`, `scr.color.bytes` are separate toggles; `scr.utf8` "show UTF-8 characters instead of ANSI". https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/cconfig.c — primary. r2pipe decodes output with `.decode("utf-8", errors="ignore")` → non-UTF8 bytes silently dropped. https://github.com/radareorg/radare2-r2pipe/blob/master/python/r2pipe/open_sync.py — primary.
- FACT: newer decompiler JSON exists (`pdgj`, `pdcj`, `pdgtj`, `pdgx`) but is plugin-version dependent; no universal JSON guarantee across all `p*` commands. https://book.rada.re/arch/decompile.html + r2ghidra README — primary.
- CLOSEST ALTERNATIVES (exact): always prefix sessions with `e scr.color=0`, `e scr.utf8=false`, `e scr.interactive=false`, `e scr.prompt=false`; prefer `ii j`/`iij`, `izzj`, `aflj`, `axj`/`axtj`, `pdcj`/`pdgj` where they exist; fall back to `cmd()` + explicit parse for commands lacking `j`, and use `~{field}` grep filter for stable text columns.

### 6. Windows / persistence / path issues

- FACT (r2pipe): on `os.name == "nt"` r2pipe appends `.exe` to `radare2`, sets `hello_cmd=False`, and reads the initial NUL **twice** ("On windows-spawn method we need to read the null byte twice"); `Popen(cmd, shell=False, stdin=PIPE, stdout=PIPE, bufsize=0)`. https://github.com/radareorg/radare2-r2pipe/blob/master/python/r2pipe/open_sync.py — 2026-11-17 — primary.
- FACT (r2pipe async): Windows uses `asyncio.ProactorEventLoop()` when owning the loop. https://github.com/radareorg/radare2-r2pipe/blob/master/python/r2pipe/open_async.py — primary.
- FACT (project paths): `is_valid_project_name()` accepts ONLY digits, lowercase ASCII letters and `_`, max 63 UTF-8 chars (uppercase/hyphen/dot rejected unless absolute path); paths built with `dir.projects` + `R_SYS_DIR`; delete refuses anything outside `dir.projects`; `P*` writes to `CON` on Windows vs `/dev/stdout` on Unix; `P!` spawns `cmd` vs `sh`. https://raw.githubusercontent.com/radareorg/radare2/master/libr/core/project.c + .../cmd_project.inc.c — primary.
- FACT (r2ghidra Windows): long-standing install failures. Issue #141 → maintainer @trufae 2025-05-31: "there are many tickets to report the same and nobody is working on that"; issue #192 umbrella; as of 2026-04 `pdg` still broken with r2 6.1.4, W64 zips missing since 6.0.2; 2026-09-21 user needed manual `SLEIGHHOME` even on 6.2.2; closed 2026-09-22 after PR #300. https://github.com/radareorg/r2ghidra/issues/141 + https://github.com/radareorg/r2ghidra/issues/192 — primary.
- FACT (r2ghidra Windows manual install): README requires `r2 -H R2_USER_PLUGINS`, copy DLL, download matching `r2ghidra_sleigh-<version>.zip`, extract `.ldefs` directly into `R2_USER_PLUGINS\r2ghidra_sleigh`; aliases still need optional SLEIGH files; `cpus` left unset so `e asm.cpu=?` completion is empty — use `pdgs`. https://github.com/radareorg/r2ghidra/blob/master/README.md — primary.
- CLOSEST ALTERNATIVES (exact): pin `e dir.projects` to an absolute workspace path, sanitize project names to `[a-z0-9_]{1,63}`, avoid `P!`/`Pze` on Windows without external zip; on Windows use r2 ≥ 6.2.2 + r2ghidra with PR #300, set `e r2ghidra.sleighhome` or `SLEIGHHOME` explicitly, and have `pdc` fallback when `pdg` missing.

## Conflicting evidence

- Dirty state: shared fact "no dirty-state API" FALSE at C level (`r_core_project_is_dirty` exists), TRUE at command/r2pipe level (no `P?` entry). Also help text for `P+` conflicts with implementation (`// xxx` fallthrough). Trust source over help.
- Async: shared fact "no true async/cancel in r2pipe" FALSE as existence claim (`open_async.py`, README async column), TRUE as semantics claim (per-command cancellation suppressed by `asyncio.shield`; process-mode has no timeout; lock serializes).
- set_type: shared fact "no direct set type equivalent" FALSE (`td`, `tl`, `afs`, `afsr`, `CF`, `pdgw`); the real limitation is custom-type rejection in `afs` (issue #17432) and r2-specific atomic type names.
- Project binary: book projects/usage.html says "There is no need to specify the file associated with the project" and "A copy of the binary ... (optional when `-e prj.files` is set)". Source shows the path is stored in `rc.r2` and required unless `prj.files`/`prj.new`/base64 used. Both true: no need to *specify* it, still need it to *exist*.
- Projects reliability: 2020 book refcard calls saving broken; current book projects chapter was rewritten with detailed usage + warning ("main devs don't use them ... we never wanted to announce it as a stable or desirable feature"). Treat as persistent maturity caution, not proof of current breakage.
- Windows r2ghidra: issue #192 closed 2026-09-22 as fixed (PR #300) — do not claim currently broken; claim "historically fragile, version-coupled, verify on target".
- `web_search` gave 0 hits for `site:` r2pipe issues twice (Parallel MCP rate limit); primary evidence obtained directly from raw source instead.
