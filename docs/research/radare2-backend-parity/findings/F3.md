## Claims

### Generic command/JSON contract (for the NDJSON worker)
- Grammar: `['][.][N][cmd[,?*j]][~filter][@[@[@]]addr!size][|>pipe] ; another command`. `j` suffix = JSON, `,` = CSV/table, `*` = r2 commands, `@` = temporary seek (restored after), `~` = internal grep. `pd 5 @ 0x100000fce`. Source S6, fetched 2026-11-17, primary.
- `~` modifiers usable for text views: `+` case-insensitive, `!` negate, `&` all words, `?` count, `:s..e` line range, `[n]`/`[n-m]` columns, `{}` JSON indent, `{path}` JSON path grep. Examples `i~:0`, `pd~mov`, `pi~[0]`, `i~0x400$`. `aflj~{.name}` verified to emit values only. Sources S6 + official binary, fetched 2026-11-17, primary.
- r2pipe Python: `r2pipe.open(path)`, `r2.cmd("aa")`, `r2.cmd("afl")`, `r2.cmdj("aflj")` (evaluates JSON, returns object); transports: spawn pipes (`r2 -0`), HTTP, TCP. Rust example reads `json["bin"]["arch"]` from `cmdj("ij")`. Source S7, fetched 2026-11-17, primary.
- Man page: "Most options are also available within the radare2 'i' command (type 'i?' for help)." `rabin2 -I` binary info, `-i` imports, `-E` global exportables, `-s` symbols, `-S` sections, `-SS` segments, `-e` entrypoint, `-M` main, `-z` strings from data sections, `-zz` raw bins, `-zzz` dump raw strings for huge files, `-N minlen:maxlen`, `-j` JSON. Source S4, fetched 2026-11-17, primary.

### 1. Overview
- `i` = "Get info from opened file"; `ij` = same in JSON. `ij` top-level keys: `core`, `bin`. `core` keys: type, file, fd, size, humansz, iorw, mode, block, format. `bin` keys: arch, baddr, binsz, bintype, bits, canary, cc, checksums, class, compiled, compiler, crypto, dbg_file, dbglink, endian, guid, havecode, injprot, intrp, laddr, lang, linenum, lsyms, machine, nx, os, pic, relocs, relro, rpath, sanitize, static, stripped, subsys, uncaps, va. Read `ij.bin.arch`, `.bits`, `.baddr`, `.os`, `.bintype`, `.class`, `.endian`, `.intrp`, `.compiler`. Sources S1 + S5 (`iI`, `ie`, `iS`, `ii`, `ir`, `iz`) + binary, fetched 2026-11-17, primary.
- `iI` binary info; `iIj` JSON = flat RBinObject (same keys as `ij.bin`, no `core` wrapper). `iIj` key list identical to `ij.bin` above. Source S1 + binary, fetched 2026-11-17, primary.
- `is` = list all symbols; `isj` JSON array. `iS` = sections/segments; `iSj` JSON array, per-entry keys: `name`, `size`, `vsize`, `type`, `perm`, `flags`, `paddr`, `vaddr`. `iSS` = memory segments; `iS.` current section; `iS=` ascii-art bars; `iSm[j|c]` sections with symbols. Source S1 (`help_msg_iS`, lines 217-228) + binary, fetched 2026-11-17, primary.
- `ie` = entrypoints; `iej` JSON array. Per-entry keys observed: `paddr`, `vaddr`, `baddr`, `laddr`, `hvaddr`, `haddr`, `type` (e.g. `program`). Variants: `iee[j]` constructors/destructors, `ies[j]` entrypoint symbols; alias `ise`. `ie=entrypoint` single value. Sources S1 (`ie[?][es]`) + binary, fetched 2026-11-17, primary.
- `iM` = main address. `iMj` JSON works (generic `j` suffix) though not listed in `i?`: `{"vaddr":9376,"paddr":9376}`. Man page `-M` = "Main (show address of main symbol)". Source S4 + S1 + binary, fetched 2026-11-17, primary.
- Architecture: `e asm.arch` (disassembler arch, e.g. `x86`), `e anal.arch` (analysis arch, e.g. `x86`), `e asm.bits` (`64`). Both read via `cmd("e asm.arch")` / `cmd("e anal.arch")`; do not confuse with `ij.bin.arch` (arch from binary headers). `-a arch` sets asm.arch (`r2 -h`), `-b bits` sets asm.bits. Sources S4 + binary, fetched 2026-11-17, primary.

### 2. Imports
- `ii` = "list the symbols imported from other libraries" (volatile: does not modify binary). `iij` = JSON array. Per-entry keys observed: `ordinal`, `bind` (`GLOBAL`/`WEAK`), `type` (`FUNC`/`NOTYPE`), `name`. Other variants: `ii*` r2 cmds, `iiq` quiet, `ii,[table-query]` (can resolve a function prototype), `iic[?]` classify imports, `ii+`/`ii-` add/remove (mutation — out of scope). Source S1 `help_msg_ii` lines 167-178 + binary, fetched 2026-11-17, primary.
- `is~sym.imp` is a text grep over all symbols; on a stripped ELF that has `sym.imp.*` flags it yields nothing (observed empty) — use `iij` for imports regardless of flags. `isj` marks imported symbols with `is_imported:true`; observed import entry keys: `name` (`imp.getenv`), `flagname` (`sym.imp.getenv`), `realname`, `ordinal`, `bind`, `size`, `unsafe`, `type`, `vaddr`, `paddr`, `is_imported`. Source S6 (`~`) + S1 (`is` help) + binary, fetched 2026-11-17, primary.
- `iE` is NOT imports: help says "exports (global symbols)". Do not use `iE` for import list. Sources S1 `help_msg_iE` lines 209-215 + S4 (`-i` imports vs `-E` exports), fetched 2026-11-17, primary.

### 3. Exports
- `iE` = global symbols; `iEj` JSON array. Per-entry keys observed: `name`, `flagname`, `realname`, `ordinal`, `bind`, `size`, `type` (`FUNC`/`OBJ`), `vaddr`, `paddr`, `is_imported` (false for exports), optional `unsafe` (e.g. `console`). Variants: `iE.` export at current address, `iE,[table-query]`. Source S1 `help_msg_iE` + binary, fetched 2026-11-17, primary.
- `is` = all symbols (imports + exports + local/global), `isj` JSON uses the same schema as `iEj` and adds a `section`-less mixed list; filter by `is_imported` boolean. `is~sym` / `is~sym.` text filters; `ise`/`ies` entrypoint symbols; `is*` r2 commands; `isj.` current symbol. Source S1 `help_msg_is` + binary, fetched 2026-11-17, primary.
- Dynamic vs global: rabin2 `-E` = "Globally exportable symbols", `-s` = symbols, `-i` = imports from libraries. `iEj` includes dynamic exports (e.g. `stdout`, `error_at_line`) with `vaddr` set and `paddr` often `18446744073709551615` (ut64 -1, no physical address). Source S4 + binary observation, fetched 2026-11-17, primary.

### 4. Strings
- `iz` = strings in data sections, `izj` = JSON array. Per-entry keys: `vaddr`, `paddr`, `ordinal`, `size`, `length`, `section`, `type` (`ascii`/`utf8`/...), `string`. `izjq` = quiet JSON (just vaddr + string). `iz.` / `izj.` = string at current address. `iz [skip] [count]` and `izz [skip] [count]`; `izc` / `izzc` = count. Source S1 `help_msg_iz` lines 186-207 + binary, fetched 2026-11-17, primary.
- `izz` = "search for strings in the whole binary", `izzj` = JSON array. Same schema as `izj` plus optional `blocks` (Unicode block names). Text table columns: nth, paddr, vaddr, len, size, section, type, string. Source S1 `help_msg_iz` + binary, fetched 2026-11-17, primary.
- Type filters are suffix letters on `iz`/`izz`: `a` ascii, `u` utf8, `w` wide/utf16, `W` wide32/utf32, `b` base64. JSON forms: `izaj`/`izzaj` etc. Also `izzz[jq]` = "dump strings from whole binary to r2 shell (for huge files)" and `izzzc` count. Source S1 lines 187-205, fetched 2026-11-17, primary.
- Min length config: `bin.str.min` ("minimum string length for r_bin", observed default 0); also `bin.str.max`, `bin.str.maxbuf` (observed default `0x00a00000`), `bin.str.align`, `bin.str.filter`, `bin.str.purge`, `bin.str.enc`, `bin.str.debase64`, `bin.str.raw`, `bin.str.real`, `bin.str.nofp`, `bin.strings` (observed true), `anal.strings` (observed false). `e strings.*` DOES NOT EXIST — correct namespace is `bin.str.*`. `izzz` reads `bin.str.min` directly (`r_config_get_i(core->config, "bin.str.min")` then `r_bin_dump_strings(bf, min, 2, ...)`). Sources S1 lines 2245-2257 + official binary `e??`, fetched 2026-11-17, primary.
- Cost: `izz` scans the whole binary via `r_bin_raw_strings` (source sets `raw=true` for `izz`, calls `bin_raw_strings`); `iz` reads strings attached to the bin object. `izzz` exists specifically "for huge files" and rabin2 `-zzz` "Dump raw strings to stdout (for huge files)". No numeric benchmark in primary docs. Filter on the Python side after `izzj` (or use `izz [skip] [count]`) rather than `izz~...` if JSON must stay parseable. Sources S1 lines 2103-2268 + S4 + S10, fetched 2026-11-17, primary.

### 5. Functions list
- `afl` = list all functions; `aflj` = JSON array. Keys observed: `addr`, `name`, `size`, `is-pure`, `realsz`, `noreturn`, `recursive`, `stackframe`, `calltype`, `cost`, `cc`, `bits`, `type`, `nbbs`, `tracecov`, `is-lineal`, `ninstrs`, `edges`, `ebbs`, `signature`, `minaddr`, `maxaddr`, `maxbbins`, `midbbins`, `ratbbins`, `indegree`, `outdegree`, `nlocals`, `nargs`, `difftype`. Read `name`, `addr`, `size`, `nbbs`, `ninstrs`, `signature`. Source S2 `help_msg_afl` lines 792-813 + binary, fetched 2026-11-17, primary.
- `aflj` returns `[]` before analysis. Source binary observation (`r2 -qc aflj` on unanalysed ELF) + S8 (`aa`/`aaa` prerequisite), fetched 2026-11-17, primary.
- `afl.` current function, `afl+` sum sizes, `afl*` r2 cmds, `afl=` ascii bars, `afla[j]` reverse call order, `aflc` count, `afll [column]` verbose, `afllj` alias to aflj, `aflm` makefile style, `afln` names only, `aflq[j]` quiet, `aflx[?*jv]` function xrefs. Source S2 lines 792-813, fetched 2026-11-17, primary.
- Sorting: `afls[a|A]` address asc/desc, `afls[b|B]` basic-block count asc/desc, `afls[s|S]` size asc/desc, `afls[n|N]` name asc/desc. Verified `aflsn; aflj` and `aflsN; aflj` reorder the JSON array. Source S2 `help_msg_afls` lines 210-222 + binary, fetched 2026-11-17, primary.
- Filtering: `afl~main` text grep (internal `~`); `afl,[query]` table query; for JSON use `aflj~{.name}` (JSON path grep) or Python-side filtering after `cmdj("aflj")`. WARN: applying `~` to `aflj` output may alter structure — prefer Python filter. Sources S2 + S6 + binary, fetched 2026-11-17, primary.
- `afi` = info of current function; `afij` JSON (same function-info schema as an `aflj` element), `afi.` current, `afii` imports used in function, `afil` verbose, `afis[t]` stats, `afix[.j]` function xrefs info. Source S2 `help_msg_afia` + binary, fetched 2026-11-17, primary.
- `afs` = get/set function signature; `afsj` JSON. Observed `afsj`: `{"name":"entry0","noreturn":false,"ret":"void","callconv":"amd64","argc":1,"args":[{"name":"arg1","type":"int64_t","cc":"rdi"}]}`; plain `afs`: `void entry0 (int64_t arg1);`. `afsr [function_name] [new_type]` is mutation (other worker). Source S2 + S8 + binary, fetched 2026-11-17, primary.

### 6. Disassembly
- `pdf` = "disassemble function in a linear way"; needs function analysis (`af`/`aa`). `pdfj` JSON top-level: `name`, `size`, `addr`, `ops[]`. `pdfs` summary, `pdfr`/`pdr` recursive, `pdfJ` formatted disasm as JSON (distinct from pdfj). Before `af`, `pdf` errors "Cannot find function at ..." while `pd` works. Sources S3 `help_msg_pdf` lines 304-311 + S8 + binary, fetched 2026-11-17, primary.
- `pdj` = JSON array of ops. Per-op keys observed: `addr`, `esil`, `refptr`, `fcn_addr`, `fcn_last`, `size`, `opcode`, `disasm`, `bytes`, `family`, `type`, `reloc`, `type_num`, `type2_num`, optional `flags` (array). Read `addr`, `size`, `opcode`/`disasm`, `bytes`, `type`, `flags`, `esil`. Source S3 `help_msg_pd` lines 313-344 + binary, fetched 2026-11-17, primary.
- Syntax: `pd N` = N instructions forward from current seek (or `@ addr`); `pd -N` = N instructions backward; `pD N` = disassemble N bytes; `pd-- N` context disassembly; `pdaj` byte-per-byte JSON; `pdb[j]` basic block; `pde[j] N` follow execution flow; `pdi` like pi with offset+bytes; `pdJ` formatted JSON; `pd, [n] [query]` table. `pd:[cmd]` runs decompiler plugin (`pd:c` pseudo, `pd:g` r2ghidra) — out of F3 scope. Sources S3 lines 313-344 + S6 (`@`), fetched 2026-11-17, primary.
- `p8 [len]` = hexpair bytes at seek; `p8j` = JSON array of integer bytes (observed `[243,15,30,250,49,237,73,137]` for `p8j 8`; plain `p8 8` = `f30f1efa31ed4989`). `p8f[j]` function bytes, `p8s` space-separated, `p8x` honors hex.cols. Source S3 `help_msg_p8` + binary, fetched 2026-11-17, primary.
- Presentation config: `e asm.bytes` (display bytes, observed true), `e asm.bytes.right`, `e asm.bytes.space`, `e asm.bytes.ascii`, `e asm.lines` (ASCII-art lines, observed true), `e asm.lines.bb/call/fcn/jmp/ret/width`, `e scr.color` (0 none, 1 ansi, 2 256, 3 truecolor; observed 3). For machine-readable views set `scr.color=0` (and avoid `~` on JSON). Source S3 + S6 + official binary `e??`, fetched 2026-11-17, primary.

### 7. Xrefs to/from
- `axt [addr]` = "find data/code references to this address"; `axtj [addr]` JSON array. Observed entry (xref to `main`): `{"from":9672,"type":"DATA","perm":"r--","opcode":"lea rdi, [main]","fcn_addr":9648,"fcn_name":"entry0","refname":"main"}`. Read `from`, `type` (`CALL`/`DATA`/`CODE`), `perm`, `opcode`, `fcn_addr`, `fcn_name`, `refname`. Source S2 `help_msg_axt` lines 1279-1287 + binary, fetched 2026-11-17, primary.
- `axf [addr]` = "find data/code references from this address"; `axfj [addr]` JSON array. Observed entry: `{"from":9672,"to":9376,"type":"DATA","perm":"r--","opcode":"lea rdi, [rip - 0x12f]"}`. Read `from`, `to`, `type`, `perm`, `opcode`. Source S2 `help_msg_axf` lines 1289-1297 + binary, fetched 2026-11-17, primary.
- Other variants: `axtg [addr]` / `axfg [addr]` = "display commands to generate graphs according to the xrefs" (NOT JSON); `axtq`/`axfq` quiet; `axt*`/`axf*` r2 commands; `axtm`/`axfm` make syntax; `afx[j]` function xrefs. Source S2 lines 1279-1297, fetched 2026-11-17, primary.
- Analysis depth: official guide states "Assuming the binary has been analysed (using `r2 -A` or `aaa`, we may have at least some xrefs to start playing with the `ax` subcommands"; `axt sym.imp.puts` example after `r2 -A`. `axlj` (all xrefs JSON) and `ax,:fancy` table also documented. Missing refs come from indirect calls, emulation, jump tables etc.; `/r` (immediate refs) and `/re` (emulated computed refs) are not part of default analysis; `aax` "analyze all xrefs as functions". Sources S9 + S2, fetched 2026-11-17, primary.
- Empty xrefs are normal: `axtj`/`axfj` at current seek (entry0) returned `[]` even after `-A`; need a target address that is actually referenced (e.g. `axtj @ <address from afxj>`), or `axt sym.imp.<name>`. Source binary observation + S9, fetched 2026-11-17, primary.

### 8. Analysis prerequisites
- `aa` = "analyze all" = all symbols and entrypoints; `aaa` = deeper analysis / autoname functions after `aa`; `aaaa` adds experimental iterations; `aaaaa` more functions after aaaa. `r2 -A` runs `aaa`; `r2 -AA` maps to `aaaa` (book: "mapping of those commands to the r2 CLI options: r2 -A, r2 -AA"). Source S8 + S2 `help_msg_aa`/`help_msg_aaa` + local `r2 -h`, fetched 2026-11-17, primary.
- `aa` alias in current source: `af@@ sym.*;af@entry0;afva`. Other stages: `aac` analyze calls, `aar` analyze data references, `aad` pointers-to-pointers, `aaf` all function relationships, `aap` preludes, `aas` symbols (`af @@= isq~[0]`), `aaS` all `sym.*` flags, `aae` ESIL refs, `aax` xrefs as functions, `aaT`, `aau`, `aaw`, `aav`. Source S2 `help_msg_aa` lines 180-208, fetched 2026-11-17, primary.
- `aaaa` internals (official guide): aa; analyze imports `af@@@i`; analyze symbols `af@@@s`; arguments/locals `afva@@@F`; calls `aac`; preludes `aap`; data refs `aar`; C++ vtables `avrr`; methods; type matching `aaft`; noreturn propagation `aanr`; strings built in code `/azs`. Guide warns "not to assume the default analysis is the best option for all cases" and that `aaaaa` may create false positives. Sources S9 + S8, fetched 2026-11-17, primary.
- Which views need analysis: `ij`/`iIj`/`iij`/`iEj`/`isj`/`iSj`/`iej`/`izj`/`izzj`/`p8j`/`pdj` work with no analysis (header/bin data + linear disasm). `aflj`/`afij`/`afsj`/`pdfj`/`axtj`/`axfj` are empty or error before analysis; run `aa`/`aaa` (or `r2 -A`) once on open. Sources S8 + S9 + binary observation, fetched 2026-11-17, primary.

## Conflicting evidence
- Task hypothesis `e strings...` is wrong: `e??strings` returned no config vars. Real namespace is `bin.str.*` (and `anal.strings`, `asm.cmt.strings`). Resolved via S1 + `e??`, 2026-11-17, primary.
- `izz?` does not print help in 6.2.2 — it ran the `izz` string dump; help is under `iz?` (which documents `izz` lines). Source binary observation + S1 `help_msg_iz`, 2026-11-17, primary.
- `iEj` help says "global symbols" while `iEj` entries include dynamic objects (`stdout`, `stderr`) with `paddr = 18446744073709551615`; `is_imported:false` distinguishes them from `isj` import entries (`is_imported:true`). S1 + binary, primary.
- `axtg`/`axfg` are graph-command generators, not JSON variants; the JSON variants are strictly `axtj`/`axfj`. S2, primary.
- `aflj` empty before analysis and xrefs empty at entry0 after analysis — could be mistaken for unsupported commands. S8/S9 + binary, primary.
- `iMj` undocumented in `i?` but works via generic `j` suffix. S1/S4 + binary, primary.
- Built-in `pdc` (pseudo C) vs plugin `pd:g` (r2ghidra) vs `pd:c`; out of F3 scope, delegated to decompile worker. S3 line 320/325, primary.
