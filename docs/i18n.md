# Monorepo i18n 维护指南

## 支持语言

- en：英文源语言，也是最终 fallback。
- zh-CN：简体中文。
- auto：用户偏好，不直接传给 translator，由运行时解析为具体 locale。

核心实现位于 packages/i18n/，包名为 @oh-my-pi/pi-i18n。它不依赖 React、TUI、浏览器或网络，只使用标准 Intl。

## Locale 优先级

### coding-agent

~~~text
--language
→ ui.language
→ OMP_LOCALE
→ LC_ALL
→ LC_MESSAGES
→ LANG
→ en
~~~

--language 和 ui.language 支持 auto、en、zh-CN。无效的显式 CLI 值会产生 usage error；无效的环境值会被忽略。

环境 locale 会先去除 POSIX 的编码/修饰后缀并把下划线归一化为连字符，例如 `zh_CN.UTF-8` 会解析为 `zh-CN`。

### Web

Stats、Collab Web 和 MetaHarness 使用：

~~~text
localStorage["omp.locale"]
→ navigator.languages
→ en
~~~

Browser Relay 是 Chrome 扩展，使用 chrome.storage.local.locale，因为扩展 Options 页面不应依赖网页 origin 的 localStorage。

## 资源组织

资源位于：

~~~text
packages/i18n/src/messages/
├── en/
└── zh-CN/
~~~

当前域：

- common：跨界面通用文案。
- tui：共享终端组件文案。
- codingAgent：coding-agent CLI/TUI 文案。
- stats：Stats dashboard 文案。
- collab：Collab Web 文案。
- metaharness：MetaHarness Web 文案。
- browserRelay：Chrome 扩展 Options 文案。

英文资源决定 key 结构。新增 key 时必须同时修改英文和中文资源：

~~~ts
export const stats = {
	language: {
		label: "Language",
	},
} as const;
~~~

~~~ts
export const stats = {
	language: {
		label: "语言",
	},
} as const;
~~~

变量使用 {name}；复数使用 one/other 分支：

~~~ts
fileCount: {
	one: "{count} file",
	other: "{count} files",
}
~~~

不要把英文原文当作 key。key 应描述语义，例如 stats.language.label。

## 翻译边界

需要翻译：内置按钮、标题、标签、placeholder、ARIA 文案、tooltip、空状态、错误外壳、CLI help 和状态提示。

保持原文：用户输入、模型输出、工具输出、文件内容、Provider/模型名、命令名、参数名、配置 key、协议字段、模型 prompt、插件/扩展自定义文案和日志。

Browser Relay 的 manifest.json 静态名称/描述也保持英文；Options 页面本身使用共享资源。

## 验证

~~~sh
bun run i18n:check
bun check
bun test packages/i18n/test
~~~

资源检查会验证：

- 英文/中文递归 key 完全一致。
- 所有变量占位符名称一致。
- 复数分支结构一致。

翻译器缺失 key 时返回安全的英文 fallback，并可通过 `createI18n(locale, { onMissingKey })` 注入诊断回调；核心包不会直接向 TUI、RPC 或结构化 stdout 写日志。

修改 Browser Relay 后还要运行：

~~~sh
bun --cwd packages/browser-relay run build
bun packages/browser-relay/scripts/check-extension-assets.ts
~~~

不要在测试中读取 TypeScript 源文件匹配字符串；应测试实际 translator 输出或实际 DOM/TUI 渲染结果。
