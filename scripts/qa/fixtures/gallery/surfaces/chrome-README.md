# pi terminal chrome reference

## Capture environment

The pi executable is the Bun-shebang entry declared by `/work/pi/packages/coding-agent/package.json`:

```text
/work/pi/packages/coding-agent/src/cli.ts
```

Each scenario used its own brand-new temporary `HOME` and fresh Git repository whose working-directory basename is exactly `pi-capture`. Before launch, only this model pin was written to `$HOME/.omp/agent/config.yml`; no `symbolPreset` or other presentation setting was seeded:

```yaml
modelRoles:
  default: anthropic/claude-fable-5
```

The driver process preserved ordinary rig environment variables but removed every ambient provider credential: `AWS_*`, `ANTHROPIC_*`, `OPENAI_*`, `GOOGLE_*`, `VERTEX_*`, `BEDROCK_*`, `ZAI_*`, `OPENROUTER_*`, the other known provider prefixes, and every variable whose name ends in `API_KEY`, `ACCESS_KEY`, `SECRET_KEY`, `AUTH_TOKEN`, `ACCESS_TOKEN`, or `REFRESH_TOKEN`. The child then received only the deterministic non-secret provider placeholder `ANTHROPIC_API_KEY=pi-chrome-reference-placeholder` plus `OMP_SKIP_SETUP=1`. The placeholder intentionally produces the rendered 401 block in the user-message captures.

The checked-in o2 driver cannot currently inject `type` or `keys` in `--no-socket` mode, so these runs used `/tmp/tui-capture.ts`, a temporary copy of `/work/o2/.omp/tools/tui.ts` whose no-socket input paths write directly to the real PTY. No pi or o2 source file was changed. Raw `raw:8388608` JSON data was written byte-for-byte to `.ansi`; the final viewport was replayed through pi's installed `@xterm/headless` 6.0.0 and written to `.txt` without trimming. Resize replay switches the emulator from 120×40 to 80×24 at the exact raw-byte boundary recorded immediately before `resize:80x24`.

## Distinguishable native-scrollback preamble and projection

Pi was invoked through executable wrapper `/tmp/pi-face-filler.sh`. Before `exec /work/pi/packages/coding-agent/src/cli.ts "$@"`, the wrapper writes exactly 30 distinguishable lines, `face-scrollback-01` through `face-scrollback-30`. PTY `ONLCR` processing records them as CRLF-terminated lines in every raw `.ansi` file. The raw files remain exact and also prove pi subsequently emits CSI `H`, `2J`, and `3J`.

For the `.txt` viewport projection only, replay removes exactly pi's CSI `\x1b[2J` and `\x1b[3J` sequences. It does not remove cursor-home, erase-line/remaining-display sequences, filler content, or any other bytes. This sequence-level mask makes retained history and placement measurable without pretending pi did not emit the forbidden wipes.

The gate compares absolute cell geometry inside each side's painted app envelope, from the first non-filler painted row through the last non-filler painted row/composer, preserving every internal blank/dead row. Region origin is reported separately as the one named divergence (pi row-1-after-wipe versus o2 bottom-inline); no other blank normalization occurs. Only pi raw `2J`/`3J` is sequence-masked for projected replay.
At 80×24, a one-row leading clip that leaves the entire remaining envelope identical is likewise reported as `region-origin`; all cells after that semantic origin remain exact.
`just face-diff --self-test-origin` proves an origin-only delta remains `MATCH` with a named `region-origin` note and exits successfully.
Color comparison is exact per terminal cell on literal rows: indexed/RGB/default-resolved foreground and background plus bold, italic, dim, and underline are retained. Both raw streams are replayed through `@xterm/headless`, so wide/combining/emoji/nerd glyphs use terminal display columns rather than JavaScript code-point counts. Wide continuation cells inherit their leading glyph's resolved tuple, and foreground/attributes on blank cells are discarded because they paint no pixels; canonical runs are therefore independent of raw SGR segmentation. One-channel RGB interpolation differences of at most one integer step canonicalize to the same rendered value. The pinned emulator dependency is installed by `just setup-tools`. Only rows whose text was changed by an existing scenario normalization rule fall back to coarse color/default/bold classes, so dynamic data does not conceal theme-value divergence elsewhere.
The one expected paint-time color departure is reported separately as the named `contrast-law` divergence: raw pi text `rgb(31,37,45)` on the assumed `rgb(12,15,18)` background becomes o2 `rgb(116,124,133)` to satisfy the 4.5:1 text floor. The classifier requires identical cell ranges, background, and attributes; it does not classify other theme-value differences. Border, CodeBorder, and Shadow use the separate 3.0 chrome floor and the captured `rgb(107,114,128)` already passes unchanged.
When a slash/autocomplete roster contains an explicitly backlog-gated command, its roster region is reported as the named `gated-command` divergence and skips color comparison for that roster region only. Welcome, composer, status, popup chrome, and every row outside the roster remain exact.
The 80×24 resize case uses the same deterministic welcome-tip index as the other o2 cases; startup verifies the pi/o2 tip corpus wrap heights at 80/120/184 columns. Tip text remains normalized by the existing `rotating-tip` rule, while deterministic selection prevents random data from changing geometry.
Observed wide-boot geometry at 184×48: row 1 is blank; the first painted app row is 2; nonblank app rows continue through 22, rows 23–24 are internal blank rows, the status/composer occupies rows 25–26, and rows 27–48 are 22 trailing dead rows. The filler is not visible after replay because pi's remaining, unmasked erase-line/remaining-display operations remove it; those operations and their geometry are intentionally preserved.
